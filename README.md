# xdv-os

XDV OS integration and image-build workspace.

`xdv-os` is responsible for orchestration only. It composes boot/runtime
components into runnable disk images and does not implement kernel/runtime logic.

## XDV-062 Integration Contract

1. Keep `xdv-os` build orchestration only.
2. Compose `boot.bin` + `kernel.bin` + xdvfs image deterministically.
3. Enforce CI boot validation in the VirtualBox BIOS profile.

## What It Builds

The pipeline produces deterministic 64 MB partitioned images:

- `xdv-os/src/xdv-os-mbr-64m.img`
- `xdv-os/src/xdv-os-uefi-64m.img`
- `xdv-os/src/xdv-os.img` (alias to MBR image)
- `xdv-os/src/xdv-os-mbr-64m.vdi` (VirtualBox sync target when enabled)

## Build

Windows:

```cmd
cd xdv-os\src
build.bat
```

Linux/macOS:

```bash
cd xdv-os/src
./build.sh
```

## Determinism

`build.bat` and `build.sh` now enforce deterministic link-input ordering.
`build_images.ps1` emits deterministic GPT/UEFI metadata so repeated builds of
unchanged inputs produce identical `boot.bin`, `kernel.bin`, and image hashes.

## CI Boot Profile

CI enforces:

- deterministic output check (two full builds + hash diff)
- VirtualBox BIOS boot profile test via `scripts/ci_virtualbox_boot_test.ps1`

The VirtualBox boot test runs on a VirtualBox-capable self-hosted runner label:
`self-hosted`, `windows`, `xdv-virtualbox`.

## Boot Contract

The active boot ownership path is:

1. `xdv-os/src/boot_sector.asm` (stage0) loads `boot.bin` only.
2. `xdv-boot` (`boot.bin`) performs splash/wait, firmware-origin recognition,
   xdvfs mount, and `/console/kernel.bin` load.
3. `boot.bin` transfers control to `kernel.bin`.
4. kernel/runtime/shell path continues under `xdv-kernel` and `xdv-runtime`.

## Build Composition

- `boot.bin` is linked from `xdv-boot` object sets with `dustlink`.
- `kernel.bin` is linked from `xdv-kernel` + `xdv-dal` + `xdv-cds` +
  `xdv-umf` + `xdv-hypervisor` + `xdv-sdbm` + `xdv-runtime` + `xdv-xdvfs`
  object sets with `dustlink`.
- `boot_sector.bin` is assembled from `xdv-os/src/boot_sector.asm` (NASM).
- image layout and preload payload are generated by
  `xdv-os/src/build_images.ps1`.

The preload payload includes `xdv-os`, `xdv-core`, `xdv-edx`, and `xdv-shell`,
and stages `console/kernel.bin` in the xdvfs image.
