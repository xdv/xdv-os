# xdv-os

XDV OS integration and image-build workspace.

`xdv-os` is responsible for composing boot/runtime components into runnable disk
images. It is not the runtime kernel itself.

## What It Builds

The build pipeline produces 64 MB partitioned images:

- `xdv-os/src/xdv-os-mbr-64m.img`
- `xdv-os/src/xdv-os-uefi-64m.img`
- `xdv-os/src/xdv-os.img` (alias to MBR image)
- `xdv-os/src/xdv-os-mbr-64m.vdi` (VirtualBox sync target when enabled)

## Build

Windows:

```cmd
cd xdv-os\src
build.bat
```

Linux/macOS:

```bash
cd xdv-os/src
./build.sh
```

## Clean

Dry run:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File xdv-os/scripts/clean_xdv_os.ps1
```

Apply:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File xdv-os/scripts/clean_xdv_os.ps1 -Apply
```

## Boot Contract

The current boot contract is:

1. `xdv-os/src/boot_sector.asm` (stage0) loads `boot.bin` only.
2. `xdv-boot` (`boot.bin`) performs splash/wait, firmware-origin recognition,
   xdvfs mount, and `/console/kernel.bin` load.
3. `boot.bin` transfers control to `kernel.bin`.
4. kernel/runtime/shell path continues under `xdv-kernel` and `xdv-runtime`.

## Build Composition

- `boot.bin` is linked from `xdv-boot` object sets with `dustlink`.
- `kernel.bin` is linked from `xdv-kernel` + `xdv-runtime` + `xdv-xdvfs`
  object sets with `dustlink`.
- `boot_sector.bin` is assembled from `xdv-os/src/boot_sector.asm` (NASM).
- image layout and preload payload are generated by
  `xdv-os/src/build_images.ps1`.

The preload payload includes `xdv-os`, `xdv-core`, `xdv-edx`, and `xdv-shell`,
and stages `console/kernel.bin` in the xdvfs image.
